# ۰۸ — نقشه راه و وضعیت

## انجام‌شده در این مخزن
- کاتالوگ ۲۷۹ سیگنال + واژه‌نامه ویژگی + فضای پارامتری، با builder و اعتبارسنجی.
- سرویس تحلیل با خط پایه، ۷ نوع آشکارساز، تلفیق، محتوا، گزارش، نگهبان؛ ۱۵ تست سبز.
- بک‌اند Laravel: مهاجرت‌ها (۲۸ جدول)، مدل‌ها، سیاست‌ها، کنترلرها، مسیرها، کانال‌ها، seederها؛ ۹ تست سبز؛ Pint سبز.
- وب‌اپ Flutter: مسیرها، احراز هویت، فهرست/جزئیات درمانگر و رزرو، رضایت دوگانه، صفحه جلسه مراجع، کنسول درمانگر با تایم‌لاین، گزارش، پنل ادمین؛ استخراج ویژگی روی دستگاه (JS، syntax-checked).
- مستندات و docker-compose.
- سه‌زبانه بودن کامل (فارسی/انگلیسی/ترکی) در کاتالوگ، سرویس تحلیل، بک‌اند و وب‌اپ با اعتبارسنجی کامل بودن ترجمه‌ها.

## نیازمند تکمیل پیش از پایلوت
| مورد | جای کار | یادداشت |
|---|---|---|
| کامپایل و تست Flutter | `flutter_app/` | SDK در محیط تولید این اسکفولد نبود؛ `flutter analyze` و اصلاحات جزئی interop لازم است |
| ASR با تفکیک گوینده | سرویس جدید یا worker | Whisper/whisper.cpp؛ ارسال به `POST /sessions/{uuid}/transcript`؛ تشخیص سؤال (علامت ؟ / لحن بالارونده) |
| بخش‌بندی موضوعی | سرویس تحلیل | فعلاً برچسب دستی درمانگر (`analysis/topic`) |
| درگاه پرداخت | `Payment`, درگاه ایرانی/بین‌المللی | جدول‌ها و رابط آماده است |
| اعلان‌ها (SMS/ایمیل/پوش) | Laravel Notifications | یادآوری نوبت، تأیید، گزارش آماده |
| job حذف طبق نگهداری | Laravel Scheduler | `data_deletion_requests` و `retention.*` |
| ویژگی‌های صوتی پیشرفته | worker صوتی | jitter/shimmer/HNR/formant/MFCC (فعلاً F0/RMS/مکث). می‌توان با WebAssembly (openSMILE/praat-parselmouth) یا سرور |
| هم‌زمانی بین‌فردی | کنسول درمانگر | نیازمند استخراج ویژگی سمت درمانگر (اختیاری) |
| بازبینی ترجمه‌های ترکی و انگلیسی توسط متخصص بالینی بومی | `catalog/translations_tr.py`, `lang/tr` | ترجمه‌ها فنی-بالینی‌اند و باید توسط درمانگر ترک‌زبان بازبینی شوند |
| کالیبراسیون آستانه‌ها | کاتالوگ | مقادیر فعلی محافظه‌کارانه و اولیه؛ با داده پایلوت و بازخورد «مرتبط/رد» درمانگران تنظیم شود |
| ذخیره اختیاری ضبط | SFU Egress + رضایت جدا | فقط با رضایت مجزا و رمزنگاری |

## گام‌های بعدی پیشنهادی
1. `flutter pub get && flutter analyze` و رفع خطاهای interop احتمالی.
2. راه‌اندازی LiveKit محلی و تست تماس دو مرورگر.
3. اتصال ASR و مشاهده رویدادهای `response_latency_*` و پرچم‌های محتوا.
4. پایلوت با درمانگران روی جلسات شبیه‌سازی‌شده؛ جمع‌آوری نرخ «مرتبط/رد» هر سیگنال برای تنظیم آستانه‌ها و پیش‌فرض‌های نمایش.
5. بازبینی حقوقی رضایت‌ها و DPIA.
